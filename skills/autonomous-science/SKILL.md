# Autonomous science

Anchor the work in the owning paper's existing research notes. Code repositories own implementation, tests and operational instructions; durable notes own the scientific argument, failed approaches and interpretation. Heavy run products may remain in approved storage with exact locators, hashes and reproduction commands. Preserve existing project structure; do not replace it with a competing report tree.

Record the question, smallest informative experiment, falsifier, tested domain, acceptance criterion, independent reference, uncertainty budget and cost before tuning. Identify permitted resources, deadlines and ownership. A working implementation, a faithful replication, an adequate model and a publishable inference are distinct achievements.

Run one evidence-producing cycle:

1. Choose a bounded experiment and state prior exposure to candidate cases. Cases used to tune or select become development data.
2. Execute a small pilot through the real entry point. Record code/input/environment identities, effective settings, commands, seeds, completion and raw failures. Show a relevant wrong case fails when feasible. Use ../simulation-validation and ../result-provenance.
3. For substantive claims, use separate fresh-context science and code/numerics challenges on a pinned candidate. See ../adversarial-science-review and references/review-contract.md. If independent execution is unavailable, label self-review and leave that gate pending.
4. Preserve every finding and disposition. Repair with evidence, retain unresolved disagreement, and recheck affected claims on the changed candidate. A reviewer who implements a repair becomes an author of that change.
5. Integrate the conclusion into the durable scientific synthesis, not just another status appendix. Preserve negative results and separate completed evidence from plans. Choose the next authorized experiment for information gained, not activity count.

Maintain a compact independence ledger: candidate, reference lineage, shared data/code/assumptions, fitting exposure, reviewer exposure, and independent for what. Same-model closure, cross-implementation agreement and independent physical validation establish different things. Derivative agreement checks the implemented function, not omitted physics.

Before an expensive run or session boundary, checkpoint the goal, current conclusion, artifact identities, outstanding gates, owned jobs and host, next exact action, and how to detect already completed work before relaunching. A notification is not a follow-on computation. Use the runtime's real continuation mechanism only if authorized; a skill cannot keep a session alive.

Close each cycle as accepted in a stated domain, provisional, refuted, or blocked. Report checks actually run, including skips, and what was compiled, rendered, committed and delivered. Missing or inconclusive review is not acceptance. Check deadlines and resource limits before dispatch; keep enough capacity for a handoff. Do not launch beyond the authorized allowance or cancel another worker's jobs.

This workflow does not grant new permission to publish, merge, message people, start schedules, or change production infrastructure. See ../records-protocol for durable record placement and ../../docs/workflow.md for release boundaries.
