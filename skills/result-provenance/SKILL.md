# Result Provenance

Log results at the point of computation. Store raw value, units, uncertainty definition, producing command/code revision, input/configuration hashes, seed/run identity, and scientific scope. Never substitute a plausible value for pending evidence.

Use stable semantic keys. Generate every presentation of the same quantity from that key with explicit rounding rules. Share the record across companion papers; do not synchronize copied macros by hand. Generate table cells and figure annotations from the same record.

Distinguish current, stale, intentionally frozen historical, curated input, and missing-producer records. A frozen result retains its original sample/domain with a visible explanation. A curated constant requires a source; it is not a measured result.

Regenerate into a clean temporary directory, compare all generated artifacts, check every result use, and trace provenance back to completed outputs. Exercise a stale/corrupt artifact to show the check fails. Document parser coverage: defined macro names alone establish neither freshness nor correctness. See ../../docs/workflow.md and the runnable ../../tools/evidence.py demonstration.

Key caches from the actual dependency closure, including calibration and environment-sensitive inputs. Reject products missing required identity stamps; do not infer freshness from timestamps. Key data at construction and assert an identifying physical invariant before caching. Record optimizer initialization, phases, restart schedule, checkpoints and the rule choosing the reported iterate. Sweep every caller and downstream summary after a convention change. See ../../docs/cardassia-lessons.md.

## Reusable logger

`scripts/texresults.py` adapts the maintained research-skills logger. Unlike the synthetic integral producer, it can log scalar results and asymmetric intervals from an analysis. Construct `ResultsLog(path, run=manifest)`, call `set` or `set_interval` with an existing producer `source`, then `write`. A manifest declares `completed: true`, `command`, `code_revision`, `environment`, `scope`, the effective `configuration` object, and a nonempty `inputs` list of `{id, sha256}`. An analytic case identifies and hashes its specification. The logger stores the producer hash and manifest per result; missing provenance, nonfinite values and reversed intervals fail.

From the skill directory, `python3 scripts/texresults.py --file macros_results.tex --run run.json set ResultName 0.5 --source analysis.py --fmt .3f` records a scalar. `python3 scripts/texresults.py --file macros_results.tex check paper.tex` checks declared provenance, generated bytes and explicit `\result{Name}` uses in that single file. It does not traverse arbitrary TeX, validate every typed number, rehash unavailable remote inputs or establish scientific correctness. The original small `tools/evidence.py` case retains its own stricter, limited manuscript grammar.

Use one writer or externally serialized build for the shared record; concurrent read-modify-write writers can lose results. A run manifest is an assertion to verify against actual outputs, not proof that a job completed. Review records before public release: commands, filenames and environment metadata can reveal private information. Do not automatically publish raw manifests or logs. Use shareable artifact identifiers in the public record while retaining restricted reconstruction evidence under controlled access.
